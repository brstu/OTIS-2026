## 2. Математические модели варианта

В проекте используются три модели из лабораторной работы №1:

| Модель | Тип | Уравнение |
| :--- | :--- | :--- |
| **Model 1.10** | Линейная дискретная модель с запаздыванием по входу | $y[k+1] = a_1 y[k] + b_1 u[k] + b_2 u[k-2]$ |
| **Model 2.2** | Нелинейная дискретная модель с насыщением входа | $y[k+1] = a y[k] + b \cdot \text{sat}(u[k]), \quad \text{sat}(u) = \min(\max(u, U_{\min}), U_{\max})$ |
| **Model 3.4** | Дифференциальная модель, рассчитываемая методом Эйлера | $y[k+1] = y[k] - \Delta t \cdot a \cdot y[k]^2, \quad \Delta t = 0.1, \; y[0] = 2$ |

Поддерживаются три типа входных сигналов (`InputSignals`):
* `Constant` — постоянный ступенчатый сигнал $u[k] = A$;
* `Impulse` — единичный импульс в начальный момент $u[0] = A$, при $k > 0$ сигнал $u[k] = 0$;
* `Harmonic` — гармоническое воздействие $u[k] = A \sin(\omega \cdot k \cdot \Delta t)$, частота $\omega > 0$ задаётся пользователем.

Для запаздывающего входа в `Model 1.10` принято нулевое начальное условие $u[k-2] = 0$ при $k < 2$. Основная программа выполняет пошаговую симуляцию, формирует интерактивный HTML-отчёт `simulation_report.html` с SVG-графиком и таблицей значений и автоматически открывает его в браузере по завершении расчёта.

## 3. Анализ устойчивости

### Model 1.10
Для анализа устойчивости линейной дискретной системы выполняется $Z$-преобразование уравнения при нулевых начальных условиях:
$$z Y(z) = a_1 Y(z) + b_1 U(z) + b_2 z^{-2} U(z)$$

Передаточная функция системы:
$$W(z) = \frac{Y(z)}{U(z)} = \frac{b_1 z^2 + b_2}{z^2(z - a_1)}$$

Характеристическое уравнение на $Z$-плоскости:
$$z^2(z - a_1) = 0$$

Корни (полюса) характеристического уравнения:
$$z_{1,2} = 0, \quad z_3 = a_1$$

Двукратный полюс $z_{1,2} = 0$ расположен в начале координат внутри единичного круга и не нарушает устойчивость. Коэффициенты $b_1$ и $b_2$ входят только в числитель передаточной функции и на расположение полюсов не влияют.

**Критерий асимптотической устойчивости:** все полюса лежат строго внутри единичного круга на $Z$-плоскости ($\vert{}z_i\vert{} < 1$), следовательно:
$$\vert{}a_1\vert{} < 1 \iff -1 < a_1 < 1$$

При $\vert{}a_1\vert{} = 1$ система находится на границе устойчивости, а при $\vert{}a_1\vert{} > 1$ выходной процесс неограниченно расходится.

### Model 2.2 и Model 3.4
* В `Model 2.2` нелинейный элемент насыщения ограничивает амплитуду входного воздействия, не изменяя полюс линейной части ($z = a$).
* `Model 3.4` описывает нелинейное дифференциальное уравнение $\frac{dy}{dt} = -a y^2$, для которого критерий по корням линейного характеристического многочлена не применяется.

### Реализация
Логика проверки вынесена в класс `StabilityAnalyzer`:
* `isFirstOrderLinearStable(double a1)` — проверяет конечность коэффициента (`std::isfinite`) и выполнение строгого неравенства $\vert{}a_1\vert{} < 1$;
* `getCharacteristicRoots(double a1)` — возвращает вектор корней `{0.0, 0.0, a1}`;
* `getWarningMessage(double a1)` — формирует предупреждение при $\vert{}a_1\vert{} \ge 1$.

Перед запуском симуляции `main.cpp` проверяет устойчивость выбранной модели и при неустойчивых параметрах выводит в консоль предупреждение:
```text
[WARNING] System is NOT asymptotically stable! Pole |z| = |a1| = 1.25 >= 1.0 (divergent or boundary behavior expected).
```

## 4. Структура проекта

Во избежание дублирования исходного кода в репозитории файлы моделей и сигналов из `task_01/src` подключаются в `CMakeLists.txt` напрямую без копирования в `task_02/src`:

```text
trunk/ii03013/
├── task_01/src/                   # Исходные файлы моделей из ЛР №1 (подключаются в CMake)
│   ├── models.h
│   ├── Model1_10.h / .cpp
│   ├── Model2_2.h / .cpp
│   ├── Model3_4.h / .cpp
│   └── InputSignals.h / .cpp
└── task_02/
    ├── CMakeLists.txt             # Конфигурация сборки, Google Test / Google Mock
    ├── run_tests.bat              # Автоматическая сборка, тесты, покрытие и HTML-отчёт
    ├── generate_html_report.py    # Генератор HTML-отчёта по тестам и покрытию
    ├── readme.md                  # Отчёт по лабораторной работе
    ├── src/
    │   ├── StabilityAnalyzer.h / .cpp  # Модуль анализа устойчивости на Z-плоскости
    │   ├── Simulation.h / .cpp         # Интерфейс сигналов, симуляция и экспорт в HTML
    │   └── main.cpp                    # Консольный интерфейс и запуск расчёта
    └── test/
        └── test_models.cpp             # Модульные тесты (Google Test и Google Mock)
```

### Назначение основных компонентов
* `StabilityAnalyzer.*` — вычисление полюсов на $Z$-плоскости, проверка условия $\vert{}a_1\vert{} < 1$ и генерация предупреждения.
* `Simulation.*` — интерфейс `IInputSignalProvider`, адаптер `StandardInputSignalProvider`, функции пошагового расчёта `runSimulation`, `runSimulationWithProvider` и экспорт графика симуляции в `simulation_report.html`.
* `models_lib` — статическая библиотека в `CMakeLists.txt`, объединяющая модели из `task_01/src` и новые модули из `task_02/src` для совместного использования основной программой `task_02` и тестами `unit_tests`.
* `generate_html_report.py` — парсер XML-результатов Google Test (`test_results.xml`) и метрик покрытия (`gcovr` / `OpenCppCoverage`), формирующий страницу `test_report.html`.
* `run_tests.bat` — командный сценарий Windows для очистки старых артефактов, сборки проекта, запуска тестов и автоматического открытия `test_report.html` в браузере.

## 5. Сборка и запуск

### Требования
* **CMake** версии 3.20 или новее;
* Компилятор с поддержкой **C++17** (MSVC / Visual Studio 2022 или MinGW-w64);
* **Python 3** для генерации HTML-отчётов (и опционально `gcovr` / `OpenCppCoverage` для сбора детального покрытия);
* Доступ к интернету при первой конфигурации CMake для загрузки Google Test v1.15.2 через `FetchContent`.

### Автоматический запуск тестов и отчёта в Windows
Из каталога `trunk/ii03013/task_02` запустите:
```bat
run_tests.bat
```
Скрипт выполняет следующие шаги:
1. Удаляет устаревшие файлы `test_results.xml`, `coverage.json`, `coverage.xml`.
2. Конфигурирует и собирает проект через CMake в папку `build`.
3. Запускает `unit_tests.exe` с сохранением результатов в `test_results.xml`.
4. При наличии в системе `OpenCppCoverage` или `gcovr` собирает метрики покрытия строк и функций.
5. Формирует `test_report.html` с помощью `generate_html_report.py` и сразу открывает отчёт в браузере.

### Ручной запуск через CMake
```bat
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

## 6. Модульные тесты

Все модульные тесты реализованы в файле `test/test_models.cpp`:

| Набор тестов (Test Suite) | Проверяемая функциональность | Кол-во тестов |
| :--- | :--- | :---: |
| `StabilityAnalyzerTest` | Устойчивые ($|a_1| < 1$) и неустойчивые ($|a_1| > 1$, `NaN`) коэффициенты, граничные значения $Z$-плоскости ($|z| = 1$, $a_1 = \pm 1$), корни уравнения | 3 |
| `ManualCalculationTest` | Сверка пошагового выхода `Model 1.10`, `Model 2.2` и `Model 3.4` с заранее выполненным ручным расчётом | 3 |
| `BoundaryValueTest` | Граничные значения нелинейности `Model 2.2` в точках $u = U_{\min}$, $u = U_{\max}$, непосредственно за границами и внутри линейной зоны | 1 |
| `PhysicsAndInvariantsTest` | Сохранение состояния покоя при $u = 0, y[0] = 0$ для всех трёх моделей; сравнение численного интегрирования `Model 3.4` по методу Эйлера с аналитическим решением $y(t) = \frac{y_0}{1 + a y_0 t}$ | 2 |
| `LinearConvergenceTest` (`TEST_P`) | Параметризованный тест сходимости `Model 1.10` к теоретическому установившемуся значению $y_\infty = \frac{b_1 + b_2}{1 - a_1} u$ для 3 наборов параметров | 3 |
| `ControlModesMockTest` | Тестирование ступенчатого, импульсного и гармонического режимов управления через подставной объект `MockInputSignalProvider` (`MOCK_METHOD` в Google Mock) | 3 |
