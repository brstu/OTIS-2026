## 1. Цель работы

Расширить программу из лабораторной работы №1 модулем анализа устойчивости линейной дискретной модели и обеспечить автоматическую проверку математических функций с помощью модульных тестов. Сборка, запуск тестов и подготовка отчётов выполняются локально с помощью CMake и `run_tests.bat`.

## 2. Математические модели варианта

В проекте сохранены три модели из лабораторной работы №1:

| Модель | Тип | Уравнение |
|---|---|---|
| Model 1.10 | Линейная дискретная модель с запаздыванием по входу | `y[k+1] = a1*y[k] + b1*u[k] + b2*u[k-2]` |
| Model 2.2 | Нелинейная дискретная модель с насыщением входа | `y[k+1] = a*y[k] + b*sat(u[k])`, `sat(u) = min(max(u, Umin), Umax)` |
| Model 3.4 | Дифференциальная модель, рассчитываемая методом Эйлера | `y[k+1] = y[k] - dt*a*y[k]^2`, `dt = 0.1`, `y[0] = 2` |

Поддерживаются три входных сигнала:

- **Constant** — постоянный ступенчатый сигнал `u[k] = A`;
- **Impulse** — импульс в начальный момент `u[0] = A`, после которого вход равен нулю;
- **Harmonic** — гармонический сигнал `A*sin(w*k*dt)`, частота `w` вводится пользователем.

Для запаздывающего входа Model 1.10 принято нулевое значение `u[k-2]` при `k < 2`. Программа рассчитывает значения модели по шагам, выводит результаты и сохраняет данные в CSV (`results.csv`) для построения графика (`src/plot.py`).

## 3. Анализ устойчивости

### Model 1.10

Для анализа устойчивости рассматривается свободный процесс, то есть `u[k] = 0`:

`y[k+1] = a1*y[k]`.

Характеристическое уравнение:

`z - a1 = 0`, корень `z = a1`.

Запаздывающий вход `b2*u[k-2]` добавляет только нулевые полюса (`z = 0`), которые лежат внутри единичной окружности и на устойчивость не влияют. Коэффициенты `b1` и `b2` корни не меняют.

Дискретная линейная модель асимптотически устойчива, если все корни строго лежат внутри единичной окружности:

`abs(z) < 1`, то есть `abs(a1) < 1`.

### Model 2.2

Насыщение стоит на входе и ограничивает сигнал, но полюс линейной части не меняет: `z - a = 0`, условие устойчивости `abs(a) < 1`.

### Model 3.4

Модель нелинейная. Линеаризация в положении равновесия `y = 0` даёт множитель `1 - 2*dt*a*y = 1`, то есть граничный случай, поэтому критерий по корням к ней не применяется (`characteristicPolynomial()` возвращает пустой вектор, предупреждение не выводится). Вручную для схемы Эйлера получено: при `y[0] = 2` и `dt = 0.1` решение сходится к нулю при `0 <= a <= 5`; этот критерий в программе не реализован.

### Реализация

Класс `StabilityAnalyzer` находит корни многочлена любой степени (формулы для степени 1 и 2, метод Дюрана–Кернера для степени 3 и выше), вычисляет спектральный радиус `max abs(z)` и принимает решение с допуском `1e-9`. Граничный случай `abs(z) = 1` не считается асимптотической устойчивостью. Анализатор обрабатывает действительные и комплексные корни, а также отклоняет не конечные коэффициенты (`std::invalid_argument`).

Каждая линейная модель сообщает свой характеристический многочлен через метод `characteristicPolynomial()`, остальное (`isStable()`, `stabilityWarning()`) реализовано один раз в базовом классе `Model`. Перед запуском симуляции программа проверяет модель и, если она неустойчива, выводит предупреждение:

```text
WARNING: Linear Model 1.10 is unstable (or on the stability boundary): max |z| = 1.5000 >= 1. The simulation may diverge.
```

    ├── test_input_signals.cpp

### Назначение основных файлов

- `models.h`, `models.cpp` — общий абстрактный интерфейс математической модели; общая реализация `isStable()` и `stabilityWarning()` через характеристический многочлен.
- `Model1_10.*`, `Model2_2.*`, `Model3_4.*` — реализации трёх моделей варианта.
- `InputSignals.*` — формирование входных сигналов (`generateInput`).
- `Simulation.*` — `buildInputSignal` и `simulate`; вынесены из `main.cpp`, чтобы их можно было тестировать.
- `StabilityAnalyzer.*` — расчёт корней характеристического уравнения и проверка устойчивости.
- `main.cpp` — ввод параметров, выбор модели, предупреждение об устойчивости, симуляция и сохранение результатов.
- `test/*.cpp` — модульные тесты.
- `run_tests.bat` — автоматическая сборка, запуск тестов и генерация отчётов в Windows.

Логика программы собирается в статическую библиотеку `lab_core`, которую используют и программа `task_02`, и тесты `task_02_tests`.

## 5. Сборка и запуск

### Требования

- CMake 3.20 или новее;
- MinGW-w64 (`g++`, `mingw32-make`) с поддержкой C++17;
- Python и `gcovr` для формирования HTML/JSON-отчёта покрытия;
- доступ к GitHub при первой сборке, поскольку Google Test и Google Mock загружаются через CMake FetchContent.

### Запуск в Windows

Из корневого каталога проекта выполните:

```bat
run_tests.bat
```

Скрипт настраивает CMake с инструментированием покрытия, компилирует проект, запускает тесты и CTest, сохраняет XML-отчёт и, если `gcovr` доступен через `PATH`, создаёт отчёты в папке `coverage` (`coverage.txt`, `index.html`, `summary.json`).

Установка `gcovr`:

```bat
py -m pip install gcovr
```

Запуск самой программы и построение графика:

```bat
build.bat
```

### Ручной запуск

```bat
cmake -S . -B build_tests -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Debug -DENABLE_COVERAGE=ON
cmake --build build_tests
ctest --test-dir build_tests --output-on-failure
```

## 6. Модульные тесты

Тесты находятся в каталоге `test`.

| Файл | Группа | Проверки |
|---|---|---|
| `test_models.cpp` | Линейная модель 1.10 | Расчёт `next()` по ручному расчёту, название, характеристический многочлен, устойчивость, предупреждение, независимость устойчивости от `b1`, `b2` |
| `test_models.cpp` | Нелинейная модель 2.2 | Граничные значения насыщения `u = Umax`, `u = Umin`, выход за пределы и внутри диапазона (параметризованный `TEST_P`), устойчивость по линейной части |
| `test_models.cpp` | Дифференциальная модель 3.4 | Шаг метода Эйлера, сравнение с аналитическим решением `y0/(1 + a*y0*t)`, первый порядок точности |
| `test_models.cpp` | Инварианты | Состояние покоя при `u = 0` и `y = 0` |
| `test_input_signals.cpp` | Входные сигналы | Ступенчатый, импульсный и гармонический сигналы, значения по умолчанию, неизвестный тип |
| `test_stability.cpp` | Анализ устойчивости | Корни степеней 1, 2, 3, комплексные корни, граница `abs(z) = 1`, устойчивость по полюсу `a` (параметризованный `TEST_P`), некорректные коэффициенты, текст предупреждения |
| `test_simulation.cpp` | Расчёт шагов | `TEST_P` по пяти наборам коэффициентов и сигналов; `TEST_P` для гармонического воздействия при четырёх частотах |
| `test_simulation.cpp` | Подмена входных сигналов | Ступенька (установившееся значение), импульс (затухание и рост), согласованность вердикта анализатора с симуляцией |
| `test_simulation.cpp` | Google Mock | `MockModel` проверяет аргументы, порядок и число вызовов `next()` внутри `simulate()` |

**Количество тестов: 94** (`test_stability.cpp` — 30, `test_models.cpp` — 28, `test_input_signals.cpp` — 9, `test_simulation.cpp` — 27). Каждый набор параметров параметризованного теста учитывается как отдельный тест.

Google Mock используется для проверки взаимодействия `simulate()` с моделью: подставной объект `MockModel` фиксирует, с какими значениями состояния, входа, запаздывающего входа и шага `dt` вызывается `next()`. Режимы управления (ступенчатый, импульсный, гармонический) дополнительно проверены подменой входных сигналов вручную заданными векторами.
