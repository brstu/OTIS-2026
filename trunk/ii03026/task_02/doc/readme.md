## Вариант 1

- Линейная модель: **Model 1.1**
- Нелинейная модель: **Model 2.3**
- Дифференциальное уравнение: **Model 3.5**

## Реализованные модели

| Блок | Модель | Тип | Название |
|:--:|:--:|:--:|---|
| 1 | 1.1 | линейная дискретная | Standard First-Order Inertial System |
| 2 | 2.3 | нелинейная дискретная | Dead-Zone Non-linearity |
| 3 | 3.5 | дифференциальное уравнение | Harmonic Driving Force |

### Математические описания и параметры

- **Model 1.1**: `y(t+1) = a*y(t) + b*u(t)` (параметры по умолчанию: `a = 0.8`, `b = 0.5`). Проверяется устойчивость по корню характеристического уравнения `z = a` (`|a| < 1`).
- **Model 2.3**: `y(t+1) = a*y(t) + b*deadzone(u(t))`, где `deadzone(u) = u - δ` при `u > δ`, `0` при `|u| <= δ`, и `u + δ` при `u < -δ` (параметры по умолчанию: `a = 0.8`, `b = 0.5`, `δ = 0.2`).
- **Model 3.5**: `dy/dt = b*sin(u)` (метод Эйлера: `y(t+1) = y(t) + dt*(b*sin(u(t)))`, параметры по умолчанию: `b = 1.0`, `dt = 0.1`).

Начальное значение `y0 = 0`, уровень ступеньки `c = 1` (все значения можно изменить при запуске программы).

## Модуль анализа устойчивости

В `task_02` реализован модуль аналитического определения устойчивости систем. Перед началом симуляции программа проверяет, не приводят ли заданные коэффициенты к расходящемуся процессу, и выводит предупреждение в консоль.

| Модель | Характеристическое уравнение | Критерий устойчивости |
|--------|------------------------------|----------------------|
| Model 1.1 | `z - a = 0` | `|a| < 1` |
| Model 2.3 | `z - a = 0` | `|a| < 1` |
| Model 3.5 | `z^2 - a1*z - a2 = 0` | Критерий Юра: `|a2| < 1` и `|a1| < 1 + a2` |

## Входные воздействия

1. Ступенчатое: `u(t) = c`
2. Импульсное: `u(0) = 1`, `u(t > 0) = 0`
3. Гармоническое: `u(t) = sin(t)`

## ООП

Созданы абстрактные базовые классы `Model` и `Input`. От класса `Model` наследуются конкретные модели:
- `LinearModel` — Model 1.1
- `NonlinearModel` — Model 2.3
- `DiffModel` — Model 3.5

От класса `Input` наследуются типы входных воздействий:
- `StepInput` — ступенчатое
- `ImpulseInput` — импульсное
- `HarmonicInput` — гармоническое

## Модульное тестирование

В `task_02/test` реализованы модульные тесты на **Google Test** и **Google Mock**:

| Категория | Файл | Тестов | Описание |
|-----------|------|--------|----------|
| Математические модели | `test_models.cpp` | 14 | Базовые расчёты, известные значения, границы |
| Анализ устойчивости | `test_stability.cpp` | 19 | Граничные значения Z-плоскости, критерий Юра |
| Симуляция + Mock | `test_simulation.cpp` | 14 | Параметризованные тесты, Google Mock для входных сигналов |
| Граничные значения | `test_boundary.cpp` | 11 | Deadzone boundaries, инварианты, сходимость |

**Всего тестов: 42**

### Особенности тестов

1. **Параметризованные тесты (`TEST_P`)** — проверка сходимости алгоритмов при различных наборах данных без дублирования кода
2. **Google Mock** — тестирование различных режимов управления (ступенчатое, импульсное, гармоническое) через подмену входных сигналов
3. **Boundary Value Testing** — проверка границ зоны нечувствительности (`u = ±δ`)
4. **Инвариантное тестирование** — при `u = 0` и `y = 0` система находится в состоянии покоя

## Сборка и запуск

Сборка осуществляется с помощью файла `build.bat` для основной программы и `run_tests.bat` для тестов:

```bat
@echo off
chcp 65001 > nul
cd /d "%~dp0"

echo ===== [1/4] CMake configure =====
cmake -S . -B build
if errorlevel 1 goto error

echo ===== [2/4] CMake build =====
cmake --build build --config Release
if errorlevel 1 goto error

set "EXE="
if exist "build\Release\ii03026_task_02.exe" set "EXE=build\Release\ii03026_task_02.exe"
if exist "build\Debug\ii03026_task_02.exe" set "EXE=build\Debug\ii03026_task_02.exe"
if exist "build\ii03026_task_02.exe" set "EXE=build\ii03026_task_02.exe"
if not defined EXE goto notfound
echo Program: %EXE%

:run
echo.
echo ===== [3/4] Run program =====
if exist results.csv del results.csv
"%EXE%"
if not exist results.csv goto noresults

echo.
echo ===== [4/4] Plot (Python + matplotlib) =====
python plot.py
goto ask

:noresults
echo results.csv was not created, skipping plot.

:ask
echo.
set "AGAIN="
set /p AGAIN="Run again with another model/input? (y/n): "
if /i "%AGAIN%"=="y" goto run
echo ===== DONE =====
exit /b 0

:notfound
echo Program ii03026_task_02.exe was not found after build.
echo Check that CMakeLists.txt contains: add_executable(ii03026_task_02 main.cpp Models.cpp Utils.cpp)
goto error

:error
echo BUILD FAILED
pause
exit /b 1
```

## Автоматизация тестов

2. Собирает проект и тесты
3. Запускает все модульные тесты через `ctest`
4. Генерирует отчёт о покрытии кода через `gcovr`

## Вывод

Программа:
- позволяет выбрать модель (одну или все) и входное воздействие;
- принимает начальные значения и коэффициенты с возможностью использования значений по умолчанию;
- проверяет устойчивость линейной и нелинейной модели (Model 1.1, Model 2.3) и дифференциальной модели (Model 3.5) перед запуском симуляции;
- выводит предупреждение в консоль при нестабильных параметрах;
- симулирует отклик систем на ступенчатое, импульсное и гармоническое воздействия;
- выводит результаты в табличном виде, сохраняет их в CSV-файлы и визуализирует графики через Python/Matplotlib;
- покрыта модульными тестами (Google Test / Google Mock) с параметризованными тест-кейсами и mock-объектами для различных режимов управления;
- проходит автоматизацию локального запуска тестов и анализа покрытия кода через `run_tests.bat`.
