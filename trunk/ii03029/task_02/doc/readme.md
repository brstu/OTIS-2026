## 2. Математические модели варианта

В рамках варианта №8 рассматриваются три математические модели:

| Модель | Тип | Уравнение |
| --- | --- | --- |
| Model 1.8 | Обобщённая авторегрессионная линейная модель | <i>y</i><sub>&tau;+1</sub> = <i>a</i><sub>1</sub>&middot;<i>y</i><sub>&tau;</sub> + <i>a</i><sub>2</sub>&middot;<i>y</i><sub>&tau;-1</sub> + <i>b</i><sub>1</sub>&middot;<i>u</i><sub>&tau;</sub> + <i>b</i><sub>2</sub>&middot;<i>u</i><sub>&tau;-1</sub> |
| Model 2.10 | Нелинейная модель со сглаживанием гиперболическим тангенсом | <i>y</i><sub>&tau;+1</sub> = <i>a</i>&middot;tanh(<i>y</i><sub>&tau;</sub>) + <i>b</i>&middot;<i>u</i><sub>&tau;</sub><sup>3</sup> |
| Model 3.2 | Дифференциальная модель чистого интегратора | <i>dy</i> / <i>dt</i> = <i>b</i>&middot;<i>u</i> |

В модуле формирования входных воздействий `InputSignal` реализованы три типа сигналов:

* **Step** (`InputSignal::step(t)`) — единичный ступенчатый сигнал (`1.0` при <i>t</i> &ge; 0 и `0.0` при <i>t</i> &lt; 0);
* **Impulse** (`InputSignal::impulse(t)`) — единичный импульс в начальный момент времени (`1.0` при <i>t</i> = 0 и `0.0` при <i>t</i> &ne; 0);
* **Harmonic** (`InputSignal::harmonic(t, omega)`) — гармонический сигнал sin(&omega;&middot;<i>t</i>).

## 3. Анализ устойчивости Model 1.8

Для анализа устойчивости линейной дискретной модели 1.8 рассматривается свободный процесс при нулевом входном воздействии (<i>u</i><sub>&tau;</sub> = 0):

<p align="center"><i>y</i><sub>&tau;+1</sub> = <i>a</i><sub>1</sub>&middot;<i>y</i><sub>&tau;</sub> + <i>a</i><sub>2</sub>&middot;<i>y</i><sub>&tau;-1</sub></p>

Подстановка решения вида <i>y</i><sub>&tau;</sub> = <i>C</i>&middot;<i>z</i><sup>&tau;</sup> приводит к характеристическому уравнению второго порядка:

<p align="center"><i>z</i><sup>2</sup> &minus; <i>a</i><sub>1</sub>&middot;<i>z</i> &minus; <i>a</i><sub>2</sub> = 0</p>

Для того чтобы оба корня характеристического уравнения строго лежали внутри единичной окружности (|<i>z</i><sub>1</sub>| &lt; 1 и |<i>z</i><sub>2</sub>| &lt; 1), в классе `StabilityAnalyzer` используется критерий устойчивости Джури для дискретных систем второго порядка:

<p align="center">
1 &minus; <i>a</i><sub>1</sub> &minus; <i>a</i><sub>2</sub> &gt; 0<br>
1 + <i>a</i><sub>1</sub> &minus; <i>a</i><sub>2</sub> &gt; 0<br>
|<i>a</i><sub>2</sub>| &lt; 1
</p>

Проверка реализована в методе `StabilityAnalyzer::isStableLinear2ndOrder(a1, a2)`. При инициализации объекта `Model_1_8` автоматически вызывается метод `StabilityAnalyzer::checkAndWarn(a1, a2)`, который выводит предупреждение в консоль, если заданные коэффициенты приводят к неустойчивому процессу.

Анализатор устойчивости применяется исключительно к линейной модели `Model 1.8`. Для нелинейной модели `Model 2.10` и дифференциальной модели `Model 3.2` требуются отдельные критерии устойчивости.

### Назначение основных файлов

* `CMakeLists.txt` и `src/CMakeLists.txt` — конфигурация сборки проекта и подключение поддиректорий `src` и `test`.
* `src/Model_1_8.h` — класс `Model_1_8`, реализующий пошаговый расчёт состояния `step(u_tau)`, сброс начальных условий `reset()` и автоматическую проверку устойчивости при создании экземпляра.
* `src/InputSignal.h` — класс `InputSignal` со статическими методами генерации ступенчатого, импульсного и гармонического воздействий.
* `src/StabilityAnalyzer.h` — класс `StabilityAnalyzer`, проверяющий выполнение условий устойчивости для коэффициентов <i>a</i><sub>1</sub>, <i>a</i><sub>2</sub> и формирующий предупреждение при неустойчивости.
* `src/coverage_reporter.cpp` — вспомогательный модуль для запуска утилиты `gcov` и формирования отчёта о покрытии кода.
* `test/CMakeLists.txt` — подключение фреймворка Google Test и регистрация тестов в CTest (`gtest_discover_tests`).
* `test/test_models.cpp` — модульные тесты инициализации и отклика `Model_1_8`, а также параметризованный набор `TEST_P` из 25 тестовых траекторий.
* `test/test_signals.cpp` — проверка корректности формирования ступенчатого и импульсного сигналов.
* `test/test_stability.cpp` — проверка распознавания устойчивых и неустойчивых наборов коэффициентов (<i>a</i><sub>1</sub>, <i>a</i><sub>2</sub>).
* `run_tests.bat` — пакетный файл для автоматической сборки проекта через CMake (MinGW Makefiles), запуска `ctest` и формирования сводки покрытия с помощью `gcovr`.

## 5. Сборка и запуск

### Требования

* CMake 3.16 или новее;
* компилятор GCC (MinGW) с поддержкой стандарта C++17 и флагов покрытия кода;

Из корневого каталога проекта выполните:

```bat
run_tests.bat
```

Скрипт создаёт каталог сборки `build`, конфигурирует проект с генератором `"MinGW Makefiles"`, собирает цель `unit_tests`, запускает тесты через `ctest --output-on-failure`, после чего формирует текстовую сводку покрытия `test_report.txt` с помощью `gcovr` (с фильтрацией строки `branches:` через `findstr`).
