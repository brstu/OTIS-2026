## Анализ устойчивости (Z-плоскость)

### Модель 1.2

$$y_{t+1}=a\,y_t+b\,u_{t-k},\qquad k\ge 1.$$

Для свободного движения (u = 0) подстановка $y_t = z^t$ даёт характеристическое уравнение $z - a = 0$, корень $z = a$. Если линию задержки рассматривать как $k$ дополнительных состояний $x_{i}(t+1)=x_{i-1}(t)$, матрица состояния получает нильпотентный блок, и полное характеристическое уравнение принимает вид

$$z^{k}\,(z-a)=0,\qquad z_1=a,\quad z_{2..k+1}=0.$$

Спектральный радиус равен $\rho=\max|z|=|a|$, поэтому:

| Условие | Корни на Z-плоскости | Вывод |
|---|---|---|
| \|a\| < 1 | внутри единичной окружности | асимптотически устойчива, ступень сходится к $b/(1-a)$ |
| \|a\| = 1 | на единичной окружности | граница устойчивости, к покою не сходится (a = 1: линейный рост, a = −1: колебания) |
| \|a\| > 1 | вне единичной окружности | неустойчива, выход расходится |

Коэффициент $b$ и задержка $k$ на устойчивость не влияют: задержка добавляет только корни $z = 0$.

### Модель 2.4 (локально)

$y_{t+1}=a\,y_t\cos y_t+b\ln(1+|u_t|)$. Линеаризация в нуле: $\partial/\partial y\,[a\,y\cos y]_{y=0}=a$, корень $z=a$, то же условие $|a|<1$. Результат справедлив локально: при $|a|>1$ нуль неустойчив, но из-за ограниченности $\cos$ траектория не обязана уходить в бесконечность.

### Модель 3.6

Для дифференциальной модели Эйлера анализ не реализован (задание требует его для линейных дискретных моделей блока 1). Программа сообщает об этом в консоли.

### Предупреждение в программе

Модуль `src/stability.hpp/.cpp`. Перед началом симуляции (после ввода коэффициентов) `main.cpp` вызывает анализ и печатает характеристическое уравнение, корни, спектральный радиус и вердикт:

```
Stability analysis: Linear model 1.2
  Characteristic equation: z^2 * (z - 1.5) = 0
  Roots on the Z-plane: z1 = 1.5, z2 = 0
  Spectral radius max|z| = 1.5
  [WARNING] A root lies outside the unit circle (max |z| = 1.5 > 1): the process is unstable and its output will diverge.
```

Для устойчивых коэффициентов выводится строка `[OK]`, для границы $|z|=1$ и неустойчивых — `[WARNING]`. Граница определяется с допуском `1e-9`.

## Что проверяют тесты

| Сценарий из задания | Где реализовано |
|---|---|
| Значения моделей, посчитанные вручную | `DelayedStepTest`, `LogStepTest`, `EulerStepTest` (TEST_P), `SimulatorTest.RealDelayedModelProducesHandCalculatedCsv` |
| Модуль устойчивости, граница \|z\| = 1 | `StabilityClassify.*`, `StableDelayedTest`, `UnstableDelayedTest`, `MarginalDelayedTest`, `DelayIndependenceTest`, `StabilityPrint.*` |
| Согласованность анализатора и симуляции | `DelayedConvergenceTest`, `DelayedDivergenceTest`, `DelayedImpulseRatioTest`, `LogConvergenceTest` |
| Граничные значения нелинейности (модель 2.4) | `LogarithmicBoundary.*`: u = 0, чётность по u, $y=\pi/2$ (cos = 0), большой вход |
| Граничные значения задержки | `DelayedControlBoundary.*`: k = 0, tau = k − 1 и tau = k, нарушение порядка tau |
| Инварианты | `ModelInvariantTest` (TEST_P): покой при u = 0, y = 0; `reset()`; `EulerInvariants.*` |
| Эйлер и аналитическое решение | `EulerVsAnalyticTest` (TEST_P по dt), `HalvingStepHalvesTheError`, `EulerExactForLinearTest` |
| Режимы управления через Google Mock | `ControlModeTest` (TEST_P × mock): ступень, импульс, гармоника |

`TEST_P` используются для расчёта шагов и сходимости без дублирования кода. В `ControlModeTest` реальная модель заменена mock-объектом `MockModel`, а `EXPECT_CALL` проверяет, какой вход и номер шага симулятор передаёт модели.

Эталонное решение для Эйлера: $dy/dt=-y^3$, $y(0)=1$, $y(t)=1/\sqrt{1+2t}$, $y(1)=1/\sqrt3\approx0.57735$. Ошибка метода Эйлера (первого порядка) падает вдвое при уменьшении шага вдвое: 0.0169 (dt = 0.1), 0.0082 (0.05), 0.0040 (0.025), 0.0020 (0.0125).

## Запуск

1. Установить CMake, MinGW-w64 (g++) и Python 3.
2. `python -m pip install gcovr`
3. Запустить `run_tests.bat` из корня `task_02`. При первом запуске скачивается Google Test (нужен интернет).

Скрипт выполняет конфигурацию с `-DOTIS_COVERAGE=ON`, сборку, `ctest`, формирует отчёты в каталоге `report/` (`gtest_report.txt/.xml`, `coverage.txt`, `coverage.html`, `coverage_summary.json`, `coverage_summary.html` (покрытие строк и функций по модулям), готовый фрагмент `readme_section.md`). Код возврата ненулевой, если тесты не прошли. Аргумент `nopause` отключает паузу в конце.

Сам симулятор: `build\src\otis_variant2.exe` (интерактивно, как в ЛР №1).
